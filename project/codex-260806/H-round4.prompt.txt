파일은 반드시 UTF-8로 디코딩해 읽어라 — PowerShell Get-Content/Select-String은 -Encoding utf8 필수, rg/cat이면 그대로.

서론·계획·다짐 금지. 지금 즉시 도구로 지정 파일을 실제로 열어 확인한 뒤 발견만 보고하라.

당신은 한국 세무·웹 도메인의 적대적 코드 리뷰어다. **R4 — 마지막 각도: 「화면이 말하는 것」과 「코드가 하는 것」의 불일치 전수 점검.**

## 왜 이 각도인가
이번 세션에서 «같은 부류»의 결함이 세 번 나왔다:
1. 개인정보 동의문은 「성명·연락처·이메일」만 적었는데 실제로는 진단요약·상세분석도 전송했다.
2. 「카톡으로 결과 전송」이 실제로는 사무소로 데이터를 보냈고, 전송 실패해도 「전달했습니다」라고 했다.
3. 종부세 폴백이 「1세대1주택 세액공제 미반영」이라 안내했는데 실제로는 «반영»하고 있었다
   (260628 에 코드가 바뀐 뒤 문구가 따라가지 않음).
셋 다 «계산은 맞는데 설명이 틀린» 결함이고, 사용자는 설명을 믿고 판단한다.

## 무엇을 볼 것 — «문구 ↔ 코드» 대조만
1. **폴백/간이 안내문이 열거한 「반영/미반영」 항목이 실제 코드와 일치하는가.**
   반영한 것을 「미반영」이라 하거나, 반영 안 한 것을 빠뜨린 곳.
2. **세율·공제액·기한·요율을 «문구에 직접 적어 둔» 곳이 상수와 일치하는가.**
   (예: 「4.75%」라 써 놓고 상수는 다른 값 / 「12억」이라 써 놓고 코드는 14억)
3. **버튼·라벨이 실제 동작을 정확히 말하는가.** 누르면 무슨 일이 일어나는지.
4. **성공/실패·완료 메시지가 실제 결과와 일치하는가.** (비동기 결과를 기다리지 않고 단정하는 곳)
5. **면책·고지 문구가 실제로 하는 처리(외부 전송·저장·AI 호출)와 일치하는가.**
   특히 「입력값은 저장하지 않습니다」라고 적은 화면에서 실제 저장·전송이 있는지.
