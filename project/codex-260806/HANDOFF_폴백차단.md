# 폴백 차단 작업 — 260806 완료

## 한 줄

**8개 계산기에 «감당 못 하는 입력이면 금액을 내지 않는» 장치를 넣었다. Codex R15~R23 수렴 완료.**

## 무슨 문제였나

세금 계산기는 정밀 계산 엔진(`jt-tax-engine.fly.dev`)을 부르고, 엔진이 안 되면 브라우저 안의
«간이 폴백»으로 대신 계산해 보여 준다. 그 폴백이 어떤 조건에서는 세액을 크게 틀리게 냈다
(상속 1.8억 과소 · 양도 5.8억 과소 등).

**방침**: 감당 못 하는 입력이면 금액을 내지 않는다.
폴백을 정교하게 고치는 길은 «엔진을 한 벌 더 만드는 것»이라 새 오류를 낳는다.

작업이 진행되면서 문제가 하나 더 드러났다 — **엔진이 살아 있어도** 모르는 필드를
조용히 유리한 쪽으로 가정하고, 그 값에 「정밀 계산」 딱지가 붙는다. 폴백보다 위험하다.

## 차단 장치가 붙은 계산기 (8종)

취득세 · 양도세 · 상속세 · 증여세 · 재산세 · 종합소득세 · 법인전환 · 종부세

붙이지 **않은** 3종과 근거 — 다시 물어보지 않도록 적어 둔다.

| 계산기 | 근거 |
|---|---|
| 부가세 | 「모름」 선지가 없는 필수 문항들 — 불확정 상태 자체가 생기지 않는다 |
| 4대보험 | 부양가족 미반영을 결과 화면이 명시. 배우자 문항 자체가 없어 일관됨 |
| 경정청구 | 엔진 호출이 없다(안내형) |

## 구조 — 계산기마다 «층»이 다르다

각 계산기에 모듈 스코프 순수 함수가 하나씩 있다:
`{acq,cgt,inh,gift,prop,inc,corp,comp}FallbackGaps(answers, calc)` → 차단사유 배열.

두 층이 있다.

| 층 | 무엇 | 어디서 걸리나 |
|---|---|---|
| ① 불확정·미지원 입력 | 「모른다」고 답했거나 엔진이 그 사실을 안 받는 것 | `runAnalysis` **맨 앞** · `fn(answers, { precise: true })` — 엔진 POST 자체를 안 보낸다 |
| ② 폴백 한계 | 간이 계산만 못 푸는 것 | 엔진 응답 **직후** · `fn(answers, calc)` |

⚠️ **8개가 다 같은 모양이 아니다** (260806 Codex R23 P2 — 이 문서가 뭉뚱그려 놨던 것을 정정).
게이트를 지우기 전에 그 파일이 어느 쪽인지 먼저 볼 것.

| 구조 | 계산기 | 실제 |
|---|---|---|
| ①+② 둘 다 | 상속 · 증여 · 취득 · 양도 | 엔진 전 `{precise:true}` ① + 엔진 후 `calc` ② |
| ②만 | 재산세 | `precise:true` 면 빈 배열 — 엔진 장애 때만 걸린다 |
| ①만 (호출 지점은 둘) | 종부세 | 지분 조건이 `precise` 와 무관해 양쪽에서 같은 결과 |
| 단일 게이트 | 종합소득세 · 법인전환 | 엔진 전 한 번뿐. 엔진 후 재판정 없음 — 폴백 자체가 없다 |

`precise: true` 를 넘기면 ②층이 빠지고 ①층만 남는다 — 그래서 엔진을 부르기 전에 쓸 수 있다.
**①+② 계산기에서 하나만 지우면 조용히 샌다.**

렌더도 같은 함수를 쓴다(규칙이 두 벌이 되면 반드시 어긋난다) — 차단이면 결과 JSX를
**아예 만들지 않고** 조기 반환한다.

차단 화면도 두 얼굴이다 — `JTFallbackBlocked` 의 `reason`:
- `'input'` … 입력을 채우면 풀린다. **재시도 버튼을 감춘다**(눌러 봐야 소용없다)
- `'engine'` … 엔진 장애. 재시도가 의미 있다

## 왜 이 구조가 됐나 (되돌리지 말 것)

네 번 새고 네 번 고쳤다. **각 단계는 앞 단계로는 못 막는 누설이었다.**

1. **헤드라인만 가림** → 계산표·카카오 버튼에 금액이 그대로 남았다
2. **조기 반환(렌더)** → 그보다 먼저 `window.claude.complete` 가 폴백 세액을 외부로 보냈다
3. **AI 호출 전 게이트** → 엔진이 «성공»하면 차단이 통째로 풀렸다 → ①층 신설
4. **엔진 응답 직후 게이트** → 불확정 값이 이미 엔진에 POST 된 뒤였다 → ①층을 엔진 전으로

## 회귀 테스트 (`npm run gate` 에 등록)

- `project/tests_fallback_block.js` — 판정 규칙. 판정 «함수 전체»를 eval 해 앱과 같은 것을 실행.

되돌림을 **실제로 주입해** 검사가 잡는 것을 확인한 목록:

| 주입 | 결과 |
|---|---|
| 게이트의 `return` 삭제 | 문자열 검사는 통과, AST 검사만 FAIL |
| helper 화살표로 감싸 우회 | FAIL (가장 안쪽 함수 비교) |
| `if (fn(...), false)` 쉼표로 결과 폐기 | FAIL (조건식 «구조» 판정) |
| `{const gaps=fn()} const gaps=[]` shadowing | FAIL (같은 이름 2회 선언은 불인정) |
| 게이트 2개 중 뒤쪽만 무력화 | 앞 4개 검사는 PASS, orphan 검사만 FAIL |
| 엔진 전 게이트만 삭제 | 종전 5개는 PASS, 엔진 전 검사 2개만 FAIL |
| `const gaps=fn(); if(gaps.length)` 변수·truthy형 | 통과 (정당한 리팩터링) |
| `if(!gaps.length){…}else{return}` | 통과 / `if(!gaps.length){return}` 은 FAIL |
| `console.debug(fn(...))` 로그 호출 | 오탐 0 |
| 게이트 앞 래퍼 «정의» + 뒤 실행 | 오탐 0 (정의만 한 함수는 순회 제외) |
| 게이트 «앞»에서 IIFE 로 엔진 즉시 실행 | FAIL (즉시 실행되는 함수는 순회한다) |
| 게이트 «앞»에서 `.then(() => callEng())` | FAIL (콜백도 실행될 수 있다) |

⚠️ **엔진 함수를 별칭으로 감싸지 말 것** — `tests_gate_ast.js` 는 직접 호출만 센다.
`const runEngine = callTransferEngine;` 처럼 쓰면 엔진 호출을 못 찾아 FAIL 난다.
데이터플로 추적까지는 하지 않기로 했다. 검사로 못 박는 대신 여기 적어 둔다.
