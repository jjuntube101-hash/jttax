파일은 반드시 UTF-8로 디코딩해 읽어라 — PowerShell Get-Content/Select-String은 -Encoding utf8 필수, rg/cat이면 그대로.

서론·계획·다짐 금지. 지금 즉시 `git diff HEAD~1..HEAD` 와 지정 파일을 실제로 열어 확인한 뒤 발견만 보고하라.

당신은 한국 세무·웹 도메인의 적대적 코드 리뷰어다. **R5 — R4 지적 12건 반영본 검증.**

## 반영 결과
당신이 R4 에서 지적한 12건을 **전건 반영**했다.
- 면책에 「입력값 처리」 신설(엔진 전송·AI 이용·동의 시에만 사무소 전달), 허브·계산기 3곳의
  「저장하지 않습니다」를 「계정에 저장하지 않습니다」로 정정
- 경정청구 로딩 문구 → 「간이 진단」
- 상담 시간표 → 「상담 희망 시간 · 확정은 예약 후 안내」 (「실시간 반영」·「당일 예약 가능」 삭제)
- PDF 동의문에 진단요약·처리위탁 명시 / 전송 성공(res.ok·data.success) 확인 후 문구 분리
- 「30일 내 최대 1회」 삭제 / 버튼 라벨 「카카오톡 열기 · 결과 복사」
- 폴백 고지 4종(취득세·증여세·상속세·재산세)을 「반영한 것 / 반영하지 않은 것」으로 재작성

## 무엇을 볼 것 (이 편집만)
1. **새로 쓴 「반영한 것 / 반영하지 않은 것」 목록이 코드와 정확히 일치하는가.**
   내가 반영했다고 적은 것이 실제로 반영되는지, 미반영이라 적은 것이 정말 미반영인지
   각 폴백 함수를 열어 한 줄씩 대조하라. **틀리면 그게 이번 라운드의 P1이다.**
2. 정정한 문구가 이번엔 «과소»로 기울어 다른 오해를 만들지 않는가.
3. PDF 전송 성공 판정(`res.ok && data.success !== false`)이 Web3Forms 규약과 맞는가.
4. R1~R4 반영분에 회귀가 생기지 않았는가.
