## 1. 작업 요약

차단 패널 자체는 `calc.precise`일 때 비활성화됩니다. 그러나 폴백 차단 상태에서 세액이 직접 표시·복사·전송되는 경로와, 조건 누락/과차단을 확인했습니다.

빠른 계산 경로 평가는 다음과 같습니다.

- 상속·증여는 차단 문항 대부분이 상세 단계에 있어, 빠른 계산에서는 실제 비거주자·사전증여·배우자 미상속을 알 수 없고 수치가 나옵니다. 구조화 답만 쓴다는 원칙에는 맞지만, “폴백이 감당 못 하는 사안에는 금액을 내지 않는다”는 강한 약속에는 맞지 않습니다.
- 취득세는 반대로 면적 미입력을 차단하므로, 엔진 장애 시 일반 주택 매매의 빠른 계산도 대부분 차단됩니다. 안전 측면에서는 타당하지만 빠른 계산 기능은 사실상 폴백을 제공하지 못합니다.
- 재산세 토지 종류는 빠른 단계에 있어 차단 가능하지만, 전년도 세액·감면·비도시지역은 빠른 단계에서 확정할 수 없습니다.

## 3. 재발 방지

차단 상태를 단일 `blocked` 변수로 결과 화면 전체와 전송 컴포넌트에 적용하는 렌더링 테스트가 필요합니다. 현재처럼 헤드라인만 조건부 처리하면 동일 유형의 누설이 다시 생깁니다.
