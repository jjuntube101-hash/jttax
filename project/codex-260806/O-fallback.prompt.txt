파일은 반드시 UTF-8로 디코딩해 읽어라 — PowerShell Get-Content/Select-String은 -Encoding utf8 필수, rg/cat이면 그대로.

서론·계획·다짐 금지. 지금 즉시 `git diff HEAD~1..HEAD` 와 지정 파일을 실제로 열어 확인한 뒤 발견만 보고하라.

당신은 한국 세무·웹 도메인의 적대적 코드 리뷰어다. **폴백 차단 구현 검증.**

## 구현한 것 — 당신이 F-round2 에서 「방향이 맞다」고 한 그 방식이다
간이 폴백이 «감당 못 하는» 입력이면 금액을 표시하지 않고 사유·재시도·상담으로 보낸다.

**공용 장치** (`Report.jsx`)
- `window.jtFallbackGaps(checks)` — `[{when, why}]` 중 참인 것의 why 만 모은다.
  자유입력(context) 해석은 쓰지 않고 «구조화된 문항 답»으로만 판정한다(당신 권고).
- `<JTFallbackBlocked gaps onRetry>` — 숫자 자리에 사유 목록·재시도 버튼

**차단 조건** (당신이 F-round2 표로 준 것을 기준으로, 내 판단을 더했다)
- 상속: 비거주자 · 배우자 미상속(spouseActual='zero') · 사전증여 · 순금융재산>0 · 동거주택 · 자녀 7명↑ 인원 미입력
- 증여: 비거주자 · 세대생략 · 혼인/출산공제 · 사전증여   (부담부는 기존 engineErr 경로가 이미 차단)
- 취득: 생애최초 감면 · 85㎡ 초과 · 주택매매인데 면적 미입력 · 다주택인데 조정지역 미정 · 토지 · 주택 상속
- 재산: 종합/별도합산 토지 · 전년도 세액 입력(세부담상한) · 건축물(지역자원시설세)
- 양도: 승계/원조합원 입주권 · 조정 1주택+입주권·분양권 동시보유 · 취득당시 조정지역 「모름」 · 전입일<취득일

**내가 당신과 다르게 판단한 것 — 반박하려면 근거를 대라**
① 종부세(ReportComprehensive)는 «차단하지 않았다». 당신은 「과세표준이 공제액을 초과하는
   모든 경우」 차단을 제안했으나, 그 폴백은 재산세공제 미반영으로 «보수적 과대»(약 15%)이고
   코드 주석도 그렇게 설계했다고 적혀 있으며, 지금은 반영/미반영 목록을 정확히 고지한다.
   전면 차단은 정상 이용자를 과하게 막는다고 봤다.
② 양도세는 «양(+) 세액 전부» 차단하지 않았다. 그 근거였던 「기본세율표가 2025년 값」은
   §55① 원문 확인 결과 오독이었고(당신도 R3 에서 철회를 인정했다), 단기세율·중과·장특은
   폴백도 맞게 계산한다. 그래서 «구조적 결함이 있는 조합»만 막았다.
③ 「과대」 방향도 차단 대상에 넣었다 — 세금이 크게 많게 나오면 이용자가 «하지 않아도 될
   포기»를 하기 때문이다(예: 취득세 일시적2주택 4,670만원 과대).

## 실측 (Claude 실행 — 당신 환경엔 node 가 없다)
- `npm run gate` 8종 전 항목 통과.
- 브라우저에서 `fetch` 를 가로채 엔진을 강제 실패시킨 뒤 상속세(배우자 미상속+동거주택) 실행
  → 금액 대신 차단 패널, 사유 2건 노출. 엔진 복구 후 재시도 → 정밀 2억 3,134만원 표시
  (폴백이 보여줬을 4,753만원과 1.8억 차이).
- `tests_fallback_block.js` 신설 — 소스에서 «실제 조건식»을 추출해 실행(문자열 비교 아님)
  + 배선 확인(패널 렌더·차단 변수 사용·precise 면 미차단). 카나리아로 검출 실증.

## 무엇을 볼 것
1. **차단 조건이 실제 폴백 코드의 «결함 범위»와 맞는가.** 막아야 하는데 «안 막은» 조합,
   반대로 «과하게 막은» 조합을 각각 지목하라.
2. 차단 시 «숫자가 새는» 경로가 남았는가 — 헤드라인 말고 표·단계별·절세전략·요약 텍스트·
   카카오 요약(kakaoSummary)·리드 전송 payload 등 어디든.
3. `calc.precise` 일 때 절대 막지 않는가(정상 이용자 차단은 더 큰 사고다).
4. `report.quick`(빠른 계산) 경로에서 차단 조건 문항이 아직 없을 때의 동작이 타당한가.
5. 회귀 테스트가 «실제로 결함을 잡는» 테스트인가.
