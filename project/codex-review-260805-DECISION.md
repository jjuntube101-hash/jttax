## 세 계산기에 공통이던 «뿌리 하나» 결함 3종

### 1. 금액 입력 파서 — `raw.replace(/[^0-9]/g,'')` (P1, 3파일 전부)
「숫자가 아닌 문자를 전부 지운다」가 **자릿수를 바꿨다**.
| 입력 | 종전 저장값 | 결과 |
|---|---|---|
| `50,000,000.00` (엑셀 복사) | `5000000000` | **100배** |
| `18e8` | `188` | 자릿수 붕괴 |
| `１，８００，０００，０００` (전각) | `''` | 진행 자체가 막힘 |
| `-100000000` (필요경비) | `100000000` | 부호가 조용히 사라져 **양수 경비** |

→ `rfMoneyDigits`/`crMoneyDigits` 신설: NFKC → 쉼표·공백·₩·「원」 제거 → `^\d+(\.\d*)?$` 일 때만 수용(소수부는 원 단위 절사) → 그 외는 **받지 않고 그 자리에서 사유 표시**.
**실측 재현**: 종부세 공시가 18억 입력이 1,800억으로 읽혀 세액 2,304,000원 → 3,353,712,000원(1,456배). 양도세는 165,000원 → 190,366,000원.

### 2. 위저드 Enter 가 선택지 클릭을 죽였다 (P1, CGT·CRE 공용)
컨테이너 `onKeyDown` 이 무조건 `e.preventDefault()` 를 걸어, **버튼 위에서 누른 Enter 의 기본동작(=클릭)** 까지 막았다. Tab 으로 「2채」에 가서 Enter → 선택은 안 되고 다음 문항으로 진행 → **기본값 1주택·비조정이 그대로 확정**.
→ `e.target.closest('button, a, textarea, select')` 이면 조기 return.
**실측**: 입력칸 Enter `defaultPrevented=true`(위저드가 처리) / 버튼 Enter `false`(브라우저 클릭 살아남) 브라우저에서 확인. 오차 최대 **563,420,000원**.
부수 효과: 「이전」 버튼에서 Enter 가 앞으로 가던 것도 함께 고쳐졌다.

### 3. 연도별 비교가 기간을 «오늘 그대로» 썼다 (P1, CGT·CRE)
「언제 팔면 유리한가」를 비교한다면서 2029년 카드도 오늘과 같은 보유·거주기간을 썼다 — **늦게 팔수록 기간이 늘어난다**는 가장 큰 변수가 빠져 있었다.
→ `rfShiftYears()` 신설. 보유·나이는 항상 +1/년, **거주는 지금도 살고 있을 때만** +1/년.
그 판단에 필요한 「지금도 그 집에 살고 계신가요?」 문항을 신설(거주 0년이면 안 물음).
**실측**: 2026년 25,173,500원 → 2027년 8,184,000원, 차이 **16,989,500원**. 카드·비교표에 그 해 기준 기간을 표시.

## 법령 오류 (1차 소스 직접 확인 — `jt-law-mcp`)

### 4. 「§37⑥ 시행령 미제정」이 사실과 달랐다 (P0, 가상자산)
화면·주석이 「시행령 미제정 [확인 필요]」라고 안내하고 계산 경로도 없었다. 실제로는:
- **시행령 §88⑤** (신설 2025.2.28, 시행 2026.7.1) — 「대통령령으로 정하는 비율」 = **100분의 50**
- **시행령 §88④** — 사유 = 가상자산사업자를 통하지 않고 취득해 장부·증빙으로 실제취득가액 확인 불가 / 국세청장 고시 사유
- **§37⑥ 후단** — 「이 경우 부대비용은 필요경비에 산입하지 아니한다」

증빙 없는 이용자는 「실제 산 금액」이 필수라 **계산 자체를 못 하고 있었다.**
→ `heldBefore==='no'` 인 줄에만 체크박스를 두고, 켜면 필요경비 = 판 금액 × 50%, **수수료 불산입**, 취득가액 입력 불요. 구보유분(§37⑤)에는 적용 안 됨.
**실측**: 1억 매도·증빙불가 → 10,450,000원.

### 5. 고지 문구의 법령 서술 오류 2건 (가상자산)
- 「여러 번 나눠 산 경우의 취득가액 산정 **순서(선입선출 등)** 시행령 위임 사항」 → 실제는 **시행령 §88① 총평균법**(이미 제정).
- **가상자산 간 교환**(시행령 §88③)이 과세 대상인데 언급조차 없었다 → 「코인을 코인으로 바꿔도 과세됩니다 · 이 계산기는 계산하지 않습니다」를 본문과 미반영 목록 양쪽에 명시.
- 2026.12.31 시가 산정(시행령 §88②)도 명시.

## 이번 작업이 남긴 교훈 3개
1. **「수렴」은 근거의 함수다.** 원문 없이 15라운드를 돌아 「수렴」했지만, 원문 하나가 들어오자
   P1 이 나왔다. 「검증 불가」로 적어 둔 항목은 수렴의 «예외»이지 수렴에 포함되지 않는다.
   → 앞으로 「검증 불가」 항목은 수렴 판정에서 제외하고 별도 추적한다.
2. **「0건」은 내 스캔 범위의 답이었다** (R35). 축 하나를 고정해 놓고 「전수」라고 불렀다 —
   `feedback_check_content_not_existence` 의 같은 실패를 반복했다.
3. **게이트를 «만든 것»과 «작동하는 것»은 다르다** (R36). 고친 로직이 JSX 안이라 테스트
   하네스 밖이었는데, 세액만 고정해 놓고 「회귀 방지 완료」라 적을 뻔했다.
