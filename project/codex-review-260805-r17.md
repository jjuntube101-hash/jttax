권장 정규화는 추출 뒤, 공백 통합 전에 다음 취지로 적용하는 것입니다.

```js
addr = addr
  .replace(/(?:\([\s,]*\)|（[\s,]*）)/g, ' ')
  .replace(/[,\s]+/g, ' ')
  .trim();
```

중첩 빈 괄호까지 제거하려면 위 빈 괄호 치환을 값이 더 이상 변하지 않을 때까지 반복하되, 각 반복이 괄호 한 쌍 이상을 제거한다는 종료 조건을 유지해야 합니다.

R16의 정확한 입력 `정릉로 305(101동 601호)`은 이제 `{ addr:'정릉로 305', dong:'101', ho:'601' }`로 해소됩니다. `정릉로 305(길음뉴타운) A101동 B102호`도 `{ addr:'정릉로 305(길음뉴타운)', dong:'A101', ho:'B102' }`로 정상이며, 괄호 속 주소명은 지워지지 않습니다.

비정상 괄호 입력은 무한루프나 예외를 일으키지 않습니다. 다만 `정릉로 305(101동 601호`는 `정릉로 305(`, `정릉로 305)101동(`는 원문 그대로 남아 엔진에 전달됩니다.

`세종특별자치시 한누리대로 2130`, `부산 해운대구 마린시티2로 33`, `산 12-3`은 동·호 정규식에 매치되지 않아 원문 보존됩니다.

원래부터 빈 괄호인 `정릉로 305()`는 `정릉로 305`가 됩니다. 삭제되는 것은 빈 표기뿐이므로 주소 의미를 잃는 부작용은 없습니다.

에폭·되묻기·목록 소유권은 추가 결함 없음입니다. 문항 ID 클로저로 에폭을 전달하고([882](/D:/jt-data/jttax-cta/project/src/ReportReform2026.jsx:882)), 이동 시 현재 문항 요청을 무효화하며([860](/D:/jt-data/jttax-cta/project/src/ReportReform2026.jsx:860)), 목록 추가도 최신 ref를 읽습니다([880](/D:/jt-data/jttax-cta/project/src/ReportReform2026.jsx:880)).

## 3. 재발 방지

`rfSplitUnit`을 UI 컴포넌트 밖의 순수 함수 테스트 대상으로 두고, 위 표의 ASCII/전각/쉼표/중첩/`B동`/도로명 숫자 입력을 회귀 테스트에 추가해야 합니다. 또한 loose 매칭과 `unit_not_found` 응답을 모킹한 `RfAddrLookup` 테스트가 필요합니다.
