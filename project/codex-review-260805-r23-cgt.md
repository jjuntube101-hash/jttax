## 1. 작업 요약

독립 전수 재감사 결과, 양도세 비교의 보유·거주기간 처리에서 P1 2건, 입력 파싱·위저드에서 P2/P3 각 1건을 발견했습니다. P0는 발견하지 못했습니다.

## 2. 발견 내역

- **[P1] · `project/src/ReportReform2026.jsx:1091-1096` · 미래 연도 비교에 보유·거주기간을 그대로 재사용합니다.**  
  화면은 “파는 해에 따라”, “언제 팔면” 2026~2029를 비교한다고 하지만, 2027~2029 계산에도 입력한 현재의 `holdYears`·`resYears`를 증가시키지 않습니다.  
  재현: 2026년 기준 양도가 20억, 취득가 10억, 1주택, 비조정 취득, 보유·거주 각 9년. 2027 카드의 코드 출력은 장특 72%, 과표 109,500,000원, 총 **25,173,500원**입니다. 같은 주택을 2027년에 매도하는 비교라면 보유·거주는 각 10년이 되어 장특 80%, 2,500만원 기본공제, 과표 55,000,000원, 총 **8,184,000원**이어야 합니다. **16,989,500원 과대**입니다.  
  수정안: 취득일·전입/전출일과 각 목표 양도일을 입력받아 목표연도별 기간을 산정하거나, 현 입력이 “각 목표연도 양도일 현재의 확정 기간”임을 명시하고 연도별 기간을 따로 입력받으십시오.

- **[P1] · `project/src/ReportReform2026.jsx:239, 274, 325, 352` 및 `1020-1046` · 법정 기간을 날짜가 아닌 사용자의 임의 소수 연수로 판정합니다.**  
  공식 조회한 소득세법 시행령 제154조는 보유기간을 취득일부터 양도일까지, 거주기간을 전입일부터 전출일까지로 정합니다. 이 구현은 날짜를 전혀 받지 않아 2년 비과세·단기세율·중과완화 2년·장특 3년·고령 특례를 정확한 일수로 판정할 수 없습니다.  
  재현: 취득일 2024-01-03, 양도일 2026-01-01인 비조정 1주택(실제 보유 2년 미만), 양도가 12억·취득가 1억·경비 0·거주 0년. UI에는 날짜를 넣을 곳이 없어 `holdYears=2`로 동일하게 표현되며 코드 출력은 **0원(비과세)** 입니다. 날짜 기준으로 2년 미만이면 비과세가 배제되어 과표 1,097,500,000원, 국세 427,935,000원, 지방소득세 42,793,500원, 합계 **470,728,500원**입니다.  
  수정안: 날짜 기반 입력·산정으로 전환하고, 일수/기간 경계값을 테스트에 추가하십시오.

- **[P2] · `project/src/ReportReform2026.jsx:919-920, 966-970` · `resYears='.'`가 유효한 0년 거주로 통과합니다.**  
  정규식은 단독 소수점 `.`을 허용하고, `rfNum('.')`은 0이 됩니다. `allowZero`인 거주기간은 오류 없이 계산됩니다.  
  재현: 양도가 20억, 취득가 10억, 1주택, 보유 12년, `resYears='.'`. 2029 코드 출력은 거주 0년으로 처리되어 총 **146,366,000원**입니다. 올바른 출력은 세액이 아니라 **“유효한 숫자를 입력하세요” 검증 오류**여야 합니다.  
  수정안: 기간 입력을 `^\d+(?:\.\d+)?$`로 제한하고, `Number.isFinite(Number(v))`를 별도 검증하십시오.

- **[P3] · `project/src/ReportReform2026.jsx:1049-1056, 955-959` · 고령 특례 문항의 선언 순서가 `showIf` 의존성과 반대입니다.**  
  `seniorLive2y`가 `seniorMove`보다 먼저 선언됐지만 `seniorMove==='yes'`일 때만 보입니다. 65세 이상 1주택자가 이주 “예”를 누르면 현재 인덱스에 새 문항이 삽입되고, 계속 거주 문항 응답 뒤 이미 답한 이주 문항을 다시 거쳐야 합니다.  
  재현: 나이 67세 → 이주 “예” → 계속 거주 “예” → 다시 “수도권 집을 팔고 비수도권으로 이주하시나요?”가 표시됩니다. 올바른 흐름은 이주 여부 후 계속거주 여부를 한 번씩만 묻고 제출하는 것입니다.  
  수정안: `seniorMove`를 `seniorLive2y` 앞에 배치하거나, `showIf` 변경 시 현재 문항 ID 기반으로 인덱스를 재정렬하십시오.

## 3. 재발 방지

`tests_rf_reform2026.js`는 순수 계산부만 `eval`하므로 위저드·입력 정규식·문항 재배치 결함을 검출하지 못합니다. 날짜 경계, 목표연도별 기간 증가, `'.'` 입력 거부, 고령 특례 문항 흐름의 UI 테스트를 추가해야 합니다.
