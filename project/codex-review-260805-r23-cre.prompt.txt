서론·계획·다짐 금지. 지금 즉시 도구로 아래 파일들을 실제로 열어 확인한 뒤 발견만 보고하라. "검토하겠습니다" 같은 착수 선언만 하고 끝내지 마라 — 반드시 파일을 읽는 도구 호출부터 시작하라.

당신은 한국 세무·웹 도메인의 적대적 코드 리뷰어다. 결함을 P0~P3로 등급화해 한국어로 보고하라.

## 배경
- 저장소 D:/jt-data/jttax-cta. 정적 사이트(React 18 UMD + @babel/standalone 브라우저 트랜스파일, 빌드 툴체인 없음).
- 대상: **2026 세제개편안 종합부동산세 계산기** (2026.8.3 재정경제부 발표 "정부안" 기준, 국회 미통과). 확정법 엔진을 쓰지 않고 프론트에서 자체 계산한다.
- 이 파일의 자매 기능(양도세 계산기·주소 자동조회)은 이미 Codex 리뷰 R1~R22를 거쳤지만, **종부세 계산 로직(rfCalcCRE) 자체를 전담해서 정밀 감사한 라운드는 지금까지 없었다** — 이번이 사실상 첫 전용 감사다. 가볍게 보지 말고 처음부터 끝까지 의심하라.
- 가능하면 jt-law-mcp/jt-tax-calc-mcp MCP 도구로 현행 종합부동산세법 조문·세율·기존(현행법) 계산기(project/src/ReportComprehensive.jsx)를 직접 조회해 대조하라. 이 개편안 계산기가 "정부 발표자료"를 반영한 것이고 현행법과 다르다는 점을 감안하되, 개편안이 손대지 않은 부분(농특세율 등)은 현행법과 같아야 하므로 그 부분은 현행법 기준으로 검증하라.

## 무엇을 확인할 것 (직접 손계산해서 대조하라)

### A. 세액 계산 정확성
- 기본공제: 실거주 14억 / 비거주 9억 갈림이 SSOT와 로직에서 일관되는가. "실거주" 판정 기준(입력 문항이 실제로 그 요건을 묻는가)이 명확한가.
- 공정시장가액비율: 연도별(2026→2027→2028) 60→70→80% 같은 인상이 SSOT에 있고, 각 연도 계산에 실제로 반영되는가(하드코딩으로 특정 연도만 다른 값이고 나머지는 복붙 실수 아닌지).
- 세율 구간(누진 과세표준 구간·세율·누진공제)이 개편안 발표자료와 일치하는가. 다주택자 세율이 있다면 그 기준(주택 수 산정 방식)도 확인.
- 다주택 합산공제 산식(예: "4억 + 5억 × 거주용가액/합계액" 류)이 실제 코드에 그대로 구현됐는가. 분모 0(합계액 0), 거주용가액>합계액(비율>1) 같은 경계에서 클램프가 있는가.
- 세액공제: 연령공제 + 장기보유공제 합산 한도(예: 80%)가 실제로 적용되는가, 아니면 둘 중 하나만 적용되거나 한도 없이 100% 넘게 합산되는가. 각 공제율 구간(연령 구간별·보유기간 구간별 %)이 정확한가.
- 재산세 중복분 공제가 있다면(이중과세 조정) 계산되는가, 아니면 생략됐는가 — 생략됐다면 세액이 과다 표시되는 것이므로 P0~P1급이다.
- 농어촌특별세 20% 가산이 올바른 기준(종부세 산출세액 또는 그 일부)에 곱해지는가.
- 종부세 과세기준일(매년 6/1)과 관련해, "연도별 비교"가 실제로 각 연도 6/1 시점 소유를 전제하는 것인지 화면 문구가 오해를 유발하지 않는가.

### B. 경계·입력값
공시가격 0/음수/극단값(1조원), 주택 수 0채, 거주용가액=합계액(비율 1), 거주용가액>합계액(입력 실수), 공제기준액과 정확히 같은 공시가격(경계에서 과세 0 vs 과세 시작 여부), 부동소수점 절사 순서.

### C. 코드 결함
- 연도별 비교 카드 렌더링에서 2026/2027/2028 세 값이 서로 다른 계산 호출 결과인지, 혹시 한 번 계산한 값을 세 칸에 복붙하고 있지 않은지.
- `RfWizard` showIf 로직으로 문항이 나타나거나 사라질 때 종부세 전용 문항(1주택/다주택, 실거주 여부)에서 인덱스가 어긋나는 경우.
- 다주택 입력(주소 여러 건 추가) 시 합산 로직이 실제로 전 주택을 더하는지, 마지막 주택 값으로 덮어쓰지 않는지.

### D. 컴플라이언스
"정부안이며 확정 아님" 고지, 세부담 상한·재산세 중복분 미반영 시 그 사실 고지가 충분한가.
