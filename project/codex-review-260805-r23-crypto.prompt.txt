파일은 반드시 UTF-8로 디코딩해 읽어라 — PowerShell Get-Content/Select-String은 -Encoding utf8 필수(CP949 콘솔), rg/cat이면 그대로 쓰면 된다.

서론·계획·다짐 금지. 지금 즉시 도구로 아래 파일들을 실제로 열어 확인한 뒤 발견만 보고하라. "검토하겠습니다" 같은 착수 선언만 하고 끝내지 마라 — 반드시 파일을 읽는 도구 호출부터 시작하라.

당신은 한국 세무·웹 도메인의 적대적 코드 리뷰어다. 결함을 P0~P3로 등급화해 한국어로 보고하라.

## 배경
- 저장소 D:/jt-data/jttax-cta. 정적 사이트(React 18 UMD + @babel/standalone 브라우저 트랜스파일, 빌드 툴체인 없음).
- 대상: **가상자산(코인) 세금 계산기**. 소득세법상 가상자산소득 과세는 **2027.1.1 시행 예정**(소득세법 부칙 §5, 아직 미시행). 확정법 엔진을 쓰지 않고 프론트에서 자체 계산한다.
- 이 기능은 R1~R11 사이 몇 차례 다뤄졌으나(의제취득가액 코인별 적용 등), 전용 전수 재감사는 이번이 사실상 처음이다. 이전 확인을 신뢰하지 말고 처음부터 다시 보라.
- 가능하면 jt-law-mcp로 소득세법 §37(가상자산소득), §84(과세최저한), §64의3(세율), 부칙(시행일) 원문을 직접 조회해 대조하라.

## 이미 자체 검증으로 확인된 것 — 다시 묻지 말고, 대신 «이게 실제로 맞는지» 코드에서 재확인만 하라
- §84 3호(과세최저한 250만원) ↔ §64의3②(기본공제 250만원) 이중 적용 없음(소득 200/250/250+1/300/500만원 손계산 대조 완료).
- 음수 소득(손실>이익) 방어 — 과표·세액 0.
- `heldBefore='no'`(2026년 말 이전 미보유)인데 `marketAt2026`(의제취득가액 기준 시가) 값이 남아 있어도 계산에 안 섞임.

## 무엇을 확인할 것 (직접 손계산해서 대조하라)

### A. 세액 계산 정확성
- **의제취득가액**: 2026.12.31 시가와 실제 취득가액 중 **큰 금액**을 취득가액으로 보는 규정(§37⑤)이 **코인별로** 개별 적용되는가, 아니면 전체 포트폴리오에 한 번만 적용되는가. 코인 여러 개를 입력했을 때 각 행마다 독립적으로 "2026년 말 이전 보유분"과 "그 이후 취득분"을 구분하는가.
- **필요경비**(§37①3호): 취득가액 + 부대비용(수수료 등)이 정확히 빠지는가. 부대비용을 입력받는 필드가 있다면 반영되는지, 없다면 그 사실이 계산 결과를 어느 정도 왜곡하는지.
- **손익통산**: 코인 A는 이익, 코인 B는 손실일 때 전체 가상자산소득에서 합산 통산되는가(현행 §37은 종목 간 통산을 허용). 통산 결과가 음수면 0으로 클램프되는가, 아니면 다음 해로 이월된다는 (틀린) 가정이 들어가 있지 않은가.
- **과세최저한**(§84 3호, 250만원 이하 비과세)과 **기본공제**(§64의3②, 250만원 공제) 두 조문이 실제로 코드에서 각각 어떻게 구현됐는지 재확인 — 위 "이미 확인됨" 항목이 실제 코드 기준으로도 맞는지 라인 번호와 함께 재검증하라.
- **세율**: 20%(지방소득세 포함 22%)가 SSOT와 계산 함수 양쪽에서 일관되는가.
- **2026년에 팔 때 vs 2027년에 팔 때 비교**: 2026년 매도분은 가상자산소득세 대상이 아니어야 한다(시행 전). 계산기가 2026년 매도를 "과세 안 됨"으로 정확히 표시하는가, 아니면 실수로 2026년 매도에도 세금을 매기는가.

### B. 경계·입력값
코인 여러 종목(3~5개) 입력, 일부 종목만 손실, 취득가액=0(에어드랍 등 특수취득 가정), 의제취득가액과 실제 취득가액이 같은 경우, 음수 입력, 매우 큰 수량(부동소수점 오차), 입력 행을 추가했다가 삭제했을 때 합산에서 유령 행이 남는지.

### C. 코드 결함
- `CrRows`의 행 추가/삭제 시 React key 안정성 — 삭제 후 재계산이 삭제된 행을 여전히 포함하지 않는지.
- 코인별 입력 필드가 비어 있을 때(`''`) `Number('')===0`으로 조용히 0 처리되어 사용자가 실수로 빈칸을 낸 것과 실제 0을 낸 것이 구분 안 되는 문제.
- 여러 행의 합계가 부동소수점 누적 오차로 마지막 절사와 어긋나는 경로.

### D. 컴플라이언스
"2027.1.1 시행 예정이며 확정 아님" 고지, 시행령 미제정 조문(§37⑥ 등)이 있다면 그 사실이 고지되는가.
