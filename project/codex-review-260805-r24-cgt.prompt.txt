파일은 반드시 UTF-8로 디코딩해 읽어라 — PowerShell Get-Content/Select-String은 -Encoding utf8 필수(CP949 콘솔), rg/cat이면 그대로 쓰면 된다.

서론·계획·다짐 금지. 지금 즉시 도구로 아래 파일들을 실제로 열어 확인한 뒤 발견만 보고하라.

당신은 한국 세무·웹 도메인의 적대적 코드 리뷰어다. 이것은 **2026 세제개편안 양도소득세 계산기**(`project/src/ReportReform2026.jsx`의 `rfCalcCGT`·`JTReportReformCGT`·`RfWizard`·`RfQuestion`)에 대한 **R24 재감사**다. R23에서 이미 아래 항목을 찾아 아직 수정하지 않은 상태다 — **이 목록은 다시 보고하지 마라**:

- 2027~2029 비교 카드가 보유·거주기간을 그대로 재사용(연도 증가분 미반영)
- 보유·거주기간을 날짜가 아닌 소수 연수로만 판정(§154 날짜 기준과 불일치)
- 거주기간 입력 `'.'`이 0년으로 통과
- 고령특례 문항(`seniorLive2y`/`seniorMove`) 선언 순서가 `showIf`와 반대라 위저드에서 같은 질문을 두 번 봄

## 이번 라운드에서 새로 파볼 영역 (위 목록과 겹치지 않는 것만 보고)
1. **상태 지속성**: 새로고침·뒤로가기·다른 서브라우트로 이동 후 복귀 시 위저드 답변이 사라지거나 꼬이는가. `RfWizard`가 `key`/`useEffect` 의존성 관리를 제대로 하는가.
2. **위저드 자체의 경쟁 상태**: 주소조회가 아니라 "다음/이전" 버튼을 빠르게 연타하거나, 응답이 오기 전에 라우트를 바꾸는 경우 발생하는 문제(언마운트 후 setState 등).
3. **입력 파싱 전반**: `rfNum`류 숫자 파싱 함수가 쉼표·전각숫자·음수 부호·지수표기(`1e9`)·공백을 어떻게 처리하는지, 화면에 표시되는 금액 포맷 함수가 원 단위를 정확히 반올림/절사하는지.
4. **접근성**: `RfWizard`/`RfQuestion`이 키보드만으로(Tab/Enter/Space) 완주 가능한가. `role`·`aria-*` 중복이나 누락.
5. **XSS/인젝션**: 사용자 입력(특히 주소 텍스트)이 `dangerouslySetInnerHTML`이나 URL에 그대로 들어가는 경로가 있는가.
6. **연도별 SSOT 배선 재검증**: `window.JT_REFORM_2026.cgt`의 2026/2027/2028/2029 각 연도 값이 `rfCalcCGT`에서 실제로 분기되어 쓰이는지, 혹시 특정 두 연도가 우연히 같은 상수를 참조해 결과가 같게 나오는(복사 실수) 경로가 있는지.
7. **다주택 중과 판정**: 주택 수를 세는 로직(입력 문항이 몇 채인지 명확히 구분하는지)과 조정대상지역 여부 조합이 SSOT 세율표의 구간과 정확히 매핑되는지.

가능하면 jt-law-mcp로 소득세법 §104(세율), §95(장특공제) 원문을 다시 조회해 대조하라.
