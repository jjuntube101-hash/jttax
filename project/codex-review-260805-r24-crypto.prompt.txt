파일은 반드시 UTF-8로 디코딩해 읽어라 — PowerShell Get-Content/Select-String은 -Encoding utf8 필수(CP949 콘솔), rg/cat이면 그대로 쓰면 된다.

서론·계획·다짐 금지. 지금 즉시 도구로 아래 파일들을 실제로 열어 확인한 뒤 발견만 보고하라.

당신은 한국 세무·웹 도메인의 적대적 코드 리뷰어다. 이것은 **가상자산(코인) 세금 계산기**(`project/src/ReportCrypto2027.jsx`)에 대한 **R24 재감사**다. R23에서 이미 아래 항목을 찾아 아직 수정하지 않은 상태다 — **이 목록은 다시 보고하지 마라** (참고로 jt-law-mcp 재조회로 두 P0 모두 조문 근거를 재확인했다: 소득세법 시행령 §88①=총평균법, §88④⑤=증빙곤란시 50% 추계필요경비):

- §37⑥/시행령 §88④·⑤(50% 추계필요경비)가 이미 시행령에 있는데 "시행령 미제정"이라 잘못 안내하고 미반영
- 동일 코인 복수 취득분의 총평균법(시행령 §88①) 계산 로직 자체가 없음
- 실제 취득가액 "0원"을 공란과 동일 취급해 계산 차단
- 큰 금액(2^53 초과)에서 IEEE-754 정밀도 손실
- 검산 스위트가 UI(행 추가/삭제 등)를 검증 안 함

## 이번 라운드에서 새로 파볼 영역 (위 목록과 겹치지 않는 것만 보고)
1. **가상자산 간 교환거래**(시행령 §88③): 코인을 코인으로 맞바꾼 경우(예: BTC→ETH)의 기타소득금액 계산 규정이 있다. 이 계산기가 "매도(현금화)"만 다루고 "교환"은 아예 다루지 않는다면, 그 사실이 사용자에게 명확히 고지되는가 — 안내 없이 교환거래를 매도가 아닌 것으로 잘못 취급해 과세 대상에서 빠뜨릴 위험이 있는가.
2. **`CrRows` 행 UI 결함**: 행 추가/삭제 시 React key가 배열 인덱스에 의존한다면, 중간 행 삭제 후 남은 행들의 입력값이 잘못된 행으로 밀려 표시되는 경로가 있는지 실제로 추적하라.
3. **상태 지속성**: 새로고침·뒤로가기 시 입력한 코인별 행 데이터가 보존되는지, 사라진다면 사용자가 입력을 다 잃는 UX 결함이 P2급인지 판단하라.
4. **접근성**: `CrRows`/`CrMoney` 입력이 키보드만으로 완주 가능한가, 스크린리더가 각 행을 구분해 읽을 수 있는가.
5. **음수·소수점 코인 수량**: 코인 수량(소수점 8자리까지 흔함)을 받는 필드가 있다면 부동소수점 반올림 오차가 세액에 누적되는지, 없다면(금액만 받는다면) 그 설계가 실제 사용자 입력 습관과 맞는지.
6. **§88⑥ 국세청장 고시사항**: SSOT나 화면에 "국세청장이 정하여 고시" 하는 세부사항이 아직 없다는 사실이 고지되는지, 아니면 마치 모든 게 확정된 것처럼 보이는 문구가 있는지.

가능하면 jt-law-mcp로 소득세법 §37, 시행령 §88을 다시 조회해 위 1·6번을 대조하라.
