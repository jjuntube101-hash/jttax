## 1. 작업 요약

신규 발견 1건입니다. 공유 `RfQuestion`/`RfWizard`의 Enter 처리 결함이 양도세 위저드에도 동일하게 적용됩니다. 계산 분기·고가주택 안분·필요경비·공제 중복·CGT SSOT 죽은 값에서는 신규 결함을 찾지 못했습니다.

## 2. 발견 내역

- **[P1] · [ReportReform2026.jsx](/D:/jt-data/jttax-cta/project/src/ReportReform2026.jsx:900), [ReportReform2026.jsx](/D:/jt-data/jttax-cta/project/src/ReportReform2026.jsx:990) · 기본 선택값과 다른 선택지에서 Enter를 누르면 선택 클릭보다 위저드 이동이 먼저 실행되어, 기본값이 확정됩니다.**

  `RfQuestion`의 선택 버튼은 `onClick`에서만 답을 바꾸고(900행), `RfWizard` 상위 div는 모든 Enter를 받아 `preventDefault()` 후 `go(1)` 합니다(990행). 따라서 선택 버튼에 포커스가 있어도 Enter의 기본 click이 막히며 `onChange(q.id, v)`가 실행되지 않습니다.

  재현 입력: 양도가액 20억원, 취득가액 10억원, 필요경비 0원, 보유 10년, 거주 0년, 나이 50세. “주택 수” 기본값 1채 상태에서 Tab으로 “2채”에 포커스 후 Enter, 이후 조정대상지역 “예”, 취득 당시 조정지역 “아니오”를 선택.

  잘못된 결과: `houses`가 기본값 `one`으로 남아 1세대 1주택 고가주택 안분 및 40% 장특이 적용되어 2026 총세액 **77,341,000원**.

  올바른 결과: 의도대로 `houses='two'`, `adjusted='yes'`이면 장특공제 배제·2주택 중과 +20%p가 적용되어 2026 총세액 **640,761,000원**. 차이 **563,420,000원**.

  같은 결함은 “조정대상지역” 기본값 `no`에서 “예”에 Enter를 누를 때도 발생합니다. 2주택 조건에서 `no`로 잘못 확정되면 **328,911,000원**, `yes`의 올바른 값은 **640,761,000원**으로 **311,850,000원 과소계산**입니다.

  수정안: 선택 버튼의 `onKeyDown`에서 Enter/Space를 소비해 값을 먼저 갱신하거나, 위저드 Enter 핸들러가 `button`/선택지 내부 이벤트이면 진행을 하지 않도록 제외하십시오. 선택 변경 후에만 다음 이동을 허용하는 UI 회귀 테스트를 추가해야 합니다.

## 3. 재발 방지

기본값이 있는 각 선택 문항에 대해 “다른 선택지 Tab → Enter”가 답변 상태를 바꾸고 현재 문항에 남는지 검증하는 UI 테스트를 고정해야 합니다.

## 4. 검증 결과

- UTF-8로 대상 JSX 및 기존 R23/R24 감사 기록을 실제 열람했습니다.
- 고가주택 안분은 `양도차익 × (양도가액−12억원) / 양도가액`을 쓰는 254행으로, 소득세법 시행령 제160조 제1항 산식과 일치합니다. [API 확인]
- 소득세법 제89조 제1항 제3호의 12억원 초과 고가주택 비과세 제외도 재확인했습니다. [API 확인]
- 필요경비는 양도차익 산정 전에 한 번 차감되고(230행), 고가주택 안분 후 장특공제도 과세대상 양도차익에만 한 번 적용됩니다(294행). 고령 감면은 그 후 산출세액에서만 차감됩니다(361~365행). 신규 중복·순서 오류 없음.
- `cgt`의 `highValueThreshold`, `shortTermRates`, `ltd`, `ltdCap`, `ltdYears`, `basicDeduct`, `basicDeductLongRes`, `surcharge`, `seniorRelief`는 모두 `rfCalcCGT`에서 실제 참조됩니다. 죽은 CGT SSOT 값 없음.
- 수기 PowerShell 검산: 기본 1주택 **77,341,000원**, 의도한 2주택 조정지역 **640,761,000원**.
- 회귀 테스트 실행은 시도했으나 `npm`/`node` 실행 파일이 환경에 없어 불가했습니다.
