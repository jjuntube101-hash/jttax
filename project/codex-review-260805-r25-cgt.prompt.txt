파일은 반드시 UTF-8로 디코딩해 읽어라 — PowerShell Get-Content/Select-String은 -Encoding utf8 필수(CP949 콘솔), rg/cat이면 그대로 쓰면 된다.

서론·계획·다짐 금지. 지금 즉시 도구로 아래 파일들을 실제로 열어 확인한 뒤 발견만 보고하라.

당신은 한국 세무·웹 도메인의 적대적 코드 리뷰어다. **2026 세제개편안 양도소득세 계산기**(`ReportReform2026.jsx`의 `rfCalcCGT`·`JTReportReformCGT`)의 **R25(최종 확인) 재감사**다. 지금까지 이미 찾아 아직 미수정인 항목 — **다시 보고하지 마라**:

- 2027~2029 비교가 보유·거주기간 미증가 / 날짜 아닌 소수연수 판정 / `'.'` 입력 0년 통과 / 고령특례 문항 순서 꼬임 / 라우트 이동·새로고침 시 답변 전부 소실 / 지수표기(`1e9`)·전각숫자 파싱 실패(0원 또는 진행불가) / 선택지에 aria-pressed 없음·포커스 이동 없음 / 요약 표기 반올림 경계 오류 / 언마운트 후 setState

## 확인 요청 1 — 다른 계산기(종부세)에서 발견된 버그가 여기도 있는가
종부세 계산기(`JTReportReformCRE`)의 R25 직전 라운드에서 이런 결함이 나왔다: **기본값이 선택된 문항에서 Tab으로 다른 선택지에 포커스한 뒤 Enter를 누르면, 선택지 클릭이 아니라 위저드의 "다음" 이동이 먼저 소비되어 원래 기본값(선택 안 한 값)이 그대로 답으로 확정된 채 다음 문항으로 진행**된다(`ReportReform2026.jsx:897-920,990` 부근). `RfQuestion`/`RfWizard`는 CGT·CRE가 공유하는 컴포넌트다. **양도세 위저드에서도 정확히 같은 방식으로 재현되는지 실제로 코드를 추적해 확인하라** — 예를 들어 "주택 수" 또는 "조정대상지역 여부" 문항에서 기본값과 다른 선택지에 Tab+Enter를 사용했을 때, 화면상 선택은 바뀐 것처럼 보이는데 실제 계산에는 기본값이 쓰이는지, 재현 입력·세액 차이를 구체적으로 제시하라.

## 확인 요청 2 — 최종 전수 훑기
`rfCalcCGT`(215~383줄) 전체를 처음부터 끝까지 다시 훑어, 지금까지 다뤄지지 않은 **분기 하나하나**(비과세 배제 시 고가주택 과세대상 비율 계산, 필요경비 처리, 여러 특례가 동시에 해당될 때의 우선순위/중복적용 방지)를 검증하라. 특히:
- 고가주택(12억 초과) 비과세 특례 시 과세대상 비율 계산식이 정확한가.
- 여러 감면·공제(장특공제 + 고령특례 등)가 동시에 해당될 때 중복 적용되거나 순서가 뒤바뀌어 세액이 왜곡되는 조합이 있는가.
- SSOT `cgt` 블록에 정의됐지만 `rfCalcCGT`가 실제로는 읽지 않는(죽은) 값이 있는가 — 있다면 화면에는 그 값이 반영된 것처럼 보이는데 실제 계산에는 빠졌을 위험이 있다.

가능하면 jt-law-mcp로 소득세법 §89(비과세) 원문을 재확인하라.
