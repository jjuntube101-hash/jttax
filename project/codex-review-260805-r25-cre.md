신규 결함 1건을 확인했습니다. 파일은 UTF-8로 실제 읽었고, 법령 원문도 조회했습니다.

## 2. 발견

- [P1] · [ReportReform2026.jsx:387](/D:/jt-data/jttax-cta/project/src/ReportReform2026.jsx:387) · `houses` 한 값만으로 `isOne`을 결정합니다. UI에도 세대원·배우자·생계공동 여부·별도세대 여부를 묻는 입력이 전혀 없습니다([1219~1243](/D:/jt-data/jttax-cta/project/src/ReportReform2026.jsx:1219)). 따라서 별거 중인 배우자가 별도 주택을 보유한 경우에도 사용자가 “1채”를 선택하면 1세대 1주택 공제와 세액공제를 모두 적용합니다.

  재현: 부부가 별거하지만 각 1주택을 보유(공시가격 합계 18억원), 본인 60세·보유 5년·거주 5년, 조정지역 아님. 화면에는 관계·생계공동 여부를 묻지 않으므로 `houses=one`, `totalValue=1,800,000,000`으로 진행 가능합니다. 코드 출력은 기본공제 12억원, 과표 3억6천만원, 산출세액 192만원, 세액공제 76만8천원, 농특세 포함 **1,382,400원**입니다. 같은 합계를 이 계산기의 비(非)1주택 분기인 `houses=two`로 계산하면 공제 9억원, 과표 5억4천만원, 세액공제 없음, 농특세 포함 **3,816,000원**입니다.

  법상 “세대”는 소유자와 그 배우자 및 생계를 같이하는 가족을 뜻하며, 배우자는 주소가 다르다는 사정만으로 자동 제외되지 않습니다. 시행령 제2조의3 제1항도 “세대원 중 1명만이 … 1주택만을 소유”해야 한다고 정합니다. 따라서 미혼 성년 자녀의 별도세대 여부는 생계공동성에 따라 달라지고, 부부 별거는 특히 1주택으로 단정하면 안 됩니다. [law.go.kr API 캐시 확인]

  수정안: 주택 수 문항 전 “배우자/생계공동 가족의 주택 포함 여부”와 “별도세대 판단 불확실”을 분리해 묻고, 배우자 보유 주택이 있으면 1주택 선택을 막거나 다주택 경로로 유도하십시오.

## 3. 재발 방지

1주택 세액공제와 기본공제 진입 전에 `isOne`을 단순 주택 수가 아닌 세대판정 확인값으로 검증하는 테스트가 필요합니다. 최소한 “배우자 별거·각 1주택” 입력은 1주택 공제 경로가 되지 않아야 합니다.

## 4. 확인 결과

- 공시가격 `0` + 주택 있음: UI는 [1271](/D:/jt-data/jttax-cta/project/src/ReportReform2026.jsx:1271)에서 “공시가격 합계를 넣어 주세요”로 제출을 차단합니다. 공개 함수에 직접 `0`을 주면 과표·산출세액·농특세는 모두 0입니다. 이 경로에서 별도 신규 오산출은 발견하지 못했습니다.
- 죽은 SSOT 값: `cre.burdenCap`만 `rfCalcCRE`에서 읽히지 않습니다([184~185](/D:/jt-data/jttax-cta/project/src/ReportReform2026.jsx:184)). 다만 결과 화면이 세부담 상한을 반영하지 않았고 실제 고지세액이 더 낮을 수 있다고 명시합니다([1377~1381](/D:/jt-data/jttax-cta/project/src/ReportReform2026.jsx:1377)). 따라서 이는 구현상 미사용 값이지만, 신규 무고지 결함으로 분류하지 않았습니다.
- 2028 세율: `light`와 `heavy`가 모두 동일하게 3억·6억·12억·25억·50억·94억 경계, **0.5%·0.7%·1.3%·2.0%·3.0%·4.0%·5.0%**로 구현됐습니다([161~167](/D:/jt-data/jttax-cta/project/src/ReportReform2026.jsx:161)). 특히 주석의 “6~12억 1.0%→1.3%”와 실제 `0.013`은 일치합니다. `heavy`는 2028년에도 공정시장가액비율 80% 판정에만 남고, 세율표 선택 결과에는 차이가 없습니다.
