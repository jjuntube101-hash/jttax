파일은 반드시 UTF-8로 디코딩해 읽어라 — PowerShell Get-Content/Select-String은 -Encoding utf8 필수(CP949 콘솔), rg/cat이면 그대로 쓰면 된다.

서론·계획·다짐 금지. 지금 즉시 도구로 아래 파일들을 실제로 열어 확인한 뒤 발견만 보고하라.

당신은 한국 세무·웹 도메인의 적대적 코드 리뷰어다. **2026 세제개편안 종합부동산세 계산기**(`ReportReform2026.jsx`의 `rfCalcCRE`·`JTReportReformCRE`)의 **R25(최종 확인) 재감사**다. 지금까지 이미 찾아 아직 미수정인 항목 — **다시 보고하지 마라**:

- 재산세 중복분 공제 누락 / 거주용 주택가액 자동조회 다건 합산 / `residentValue` 음수 미클램프 / 지수표기·전각숫자 파싱 실패 / 기본값 선택지 Tab+Enter로 다른 답이 무시되는 위저드 버그 / 공동명의 1주택 특례 미신청 시에도 자동으로 1세대1주택 세액공제 적용 / 라우트 이동·새로고침 시 답변 전부 소실

## 확인 요청 1 — 공동명의 판정을 더 파라
방금 찾은 "공동명의 특례 미신청 시에도 자동 적용" 결함과 별개로, **1세대 판정 자체**를 확인하라: 별도세대 요건(시행령 제2조의3), 세대원이 다른 주소에 각자 집을 가진 경우("1세대 1주택"이 아니라 "세대별 합산 다주택"이 되는 경우)를 계산기가 구분해서 묻는가, 아니면 "주택 수" 하나만으로 전부 처리하는가. 세대 분리·미혼 단독세대·부부 별거 같은 입력을 구분 못 해 실제로는 다주택 세대인데 1주택으로 계산되는 경로가 있는지 재현 입력과 함께 제시하라.

## 확인 요청 2 — 최종 전수 훑기
`rfCalcCRE`(384~466줄) 전체를 처음부터 끝까지 다시 훑어, 지금까지 다뤄지지 않은 **분기**를 검증하라. 특히:
- 종부세 과세대상(주택분)이 아닌 입력(예: 공시가격 0인데 "주택 있음"으로 답한 경우)에서 계산이 어떻게 처리되는가.
- SSOT `cre` 블록에 정의됐지만 `rfCalcCRE`가 실제로는 읽지 않는(죽은) 값이 있는가.
- 2028년 이후 "가액 기준 세율 일원화"가 실제로 어떤 임계값·세율표로 구현됐는지, 그 임계값이 SSOT 주석의 발표자료 수치와 일치하는지 코드만으로 재확인하라(이미 "우연한 동일값 아님"으로 확인된 연도 분기 자체 말고, 세율표 «값»의 출처 주석과 실제 숫자가 맞는지).

가능하면 jt-law-mcp로 종합부동산세법 시행령 제2조의3(1세대1주택 판정) 원문을 재확인하라.
