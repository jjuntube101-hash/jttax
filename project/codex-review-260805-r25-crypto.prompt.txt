파일은 반드시 UTF-8로 디코딩해 읽어라 — PowerShell Get-Content/Select-String은 -Encoding utf8 필수(CP949 콘솔), rg/cat이면 그대로 쓰면 된다.

서론·계획·다짐 금지. 지금 즉시 도구로 아래 파일들을 실제로 열어 확인한 뒤 발견만 보고하라.

당신은 한국 세무·웹 도메인의 적대적 코드 리뷰어다. **가상자산(코인) 세금 계산기**(`ReportCrypto2027.jsx`)의 **R25(최종 확인) 재감사**다. 지금까지 이미 찾아 아직 미수정인 항목 — **다시 보고하지 마라**:

- §37⑥/시행령 §88④⑤(50% 추계필요경비) 미반영·낡은 "시행령 미제정" 안내 / 총평균법(시행령 §88①) 계산 로직 부재 / 취득가액 0원을 공란과 동일 취급 / 큰 금액에서 부동소수점 정밀도 손실 / 검산 스위트가 UI 미검증 / 가상자산 간 교환거래(시행령 §88③) 미반영·미고지 / 새로고침 시 입력 전부 소실 / 행별 접근성 라벨 부재

## 확인 요청 1 — 다른 두 계산기(양도세·종부세)에서 발견된 숫자 파싱 버그가 여기도 있는가
양도세·종부세 계산기에서 이런 버그가 확인됐다: 금액 입력에 지수표기(`1e9`, `18e8`)를 넣으면 숫자 필터가 "e"를 지워 자릿수가 완전히 다른 값(예: `1800000000`→`188`)이 되고, 전각 숫자(`１，８００，０００，０００`)는 빈 값으로 사라져 진행 자체가 막힌다. 이 계산기의 `CrMoney`/`crCalc` 금액 입력에도 **동일한 파싱 함수 또는 동일한 결함 패턴**이 있는지 실제로 코드를 추적해 확인하고, 있다면 재현 입력과 잘못된 세액을 제시하라.

## 확인 요청 2 — 최종 전수 훑기
`crCalc`(67~109줄) 전체를 처음부터 끝까지 다시 훑어, 지금까지 다뤄지지 않은 분기를 검증하라. 특히:
- 여러 코인 행 중 일부만 "2026년 말 이전부터 보유"이고 나머지는 "2027년 이후 취득"인 **혼합 입력**에서 각 행이 올바른 규칙(의제취득가액 적용 여부)으로 개별 계산되는가 — R23의 C9 테스트가 이미 통과한다고 보고됐는데, 실제 코드 로직도 그와 일치하는지 재확인하라.
- SSOT `JT_CRYPTO_2027`에 정의됐지만 `crCalc`가 실제로는 읽지 않는(죽은) 값이 있는가.
- 2026년 매도(비과세 대상)와 2027년 매도가 **같은 화면에서 동시에** 입력될 수 있다면, 두 그룹이 서로 섞여 합산되지 않는가.

가능하면 jt-law-mcp로 소득세법 §37 전체를 재확인하라.
