파일은 반드시 UTF-8로 디코딩해 읽어라 — PowerShell Get-Content/Select-String은 -Encoding utf8 필수(CP949 콘솔), rg/cat이면 그대로 쓰면 된다.

서론·계획·다짐 금지. 지금 즉시 도구로 파일을 실제로 열어 확인한 뒤 발견만 보고하라.

당신은 한국 세무·웹 도메인의 적대적 코드 리뷰어다. **2026 세제개편안 양도소득세 계산기**(`ReportReform2026.jsx`)의 **R26 — 지금까지 3라운드(R23~R25)가 찾은 것을 모두 반영한 최종 소진 라운드**다. 지금까지 이미 발견되어 아직 미수정 상태인 전체 목록 — **절대 다시 보고하지 마라**:

1. 2027~2029 비교가 보유·거주기간 미증가
2. 보유·거주기간을 날짜 아닌 소수 연수로만 판정
3. 거주기간 `'.'` → 0년 통과
4. 고령특례 문항 순서가 showIf와 반대
5. 라우트 이동·새로고침 시 답변 전부 소실
6. 지수표기(`1e9`)·전각숫자 파싱 실패(0원 또는 진행 불가)
7. 선택지에 `aria-pressed` 없음, 문항 전환 시 포커스 이동 없음
8. 요약 표기(`rfEok`) 반올림으로 경계값이 억 단위 위로 올라감
9. 주소조회 중 라우트 이동 시 언마운트된 컴포넌트에 setState
10. 기본값과 다른 선택지에 Tab 후 Enter를 누르면 선택이 무시되고 위저드가 진행됨(최대 5억원대 오차)

이 10건은 코드 상태가 그대로이므로 다시 물어도 똑같이 나온다. **완전히 새로운 카테고리만** 찾아라. 힌트:
- 인쇄(`window.print`) 또는 모바일 좁은 화면(320px)에서 레이아웃이 깨져 숫자가 잘리거나 겹치는 곳이 있는가.
- 뒤로가기 여러 번 반복, 같은 탭에서 CGT↔CRE를 반복 왕복할 때 컴포넌트 간 상태(예: `window` 전역 변수, epoch 카운터)가 서로 오염되는가.
- 계산 결과 화면의 "요약 카드"에 표시되는 문구와 `RfSteps`에 표시되는 단계별 숫자가 서로 다른 반올림 규칙을 써서 화면상 두 숫자가 미세하게 어긋나는가(사용자가 "왜 숫자가 안 맞지"라고 신고할 만한 수준).
- 필요경비 입력이 음수이거나 양도가액보다 큰 경우.
- `RfCrossLinks`가 현재 계산기 자기 자신으로 링크를 걸어 위저드 상태를 잃게 만드는 경로가 있는가.
