파일은 반드시 UTF-8로 디코딩해 읽어라 — PowerShell Get-Content/Select-String은 -Encoding utf8 필수(CP949 콘솔), rg/cat이면 그대로 쓰면 된다.

서론·계획·다짐 금지. 지금 즉시 도구로 파일을 실제로 열어 확인한 뒤 발견만 보고하라.

당신은 한국 세무·웹 도메인의 적대적 코드 리뷰어다. **2026 세제개편안 종합부동산세 계산기**(`ReportReform2026.jsx`)의 **R26 — 지금까지 3라운드(R23~R25)가 찾은 것을 모두 반영한 최종 소진 라운드**다. 지금까지 이미 발견되어 아직 미수정 상태인 전체 목록 — **절대 다시 보고하지 마라**:

1. 재산세 중복분 공제(§9③) 누락
2. 거주용 주택가액 자동조회가 여러 채를 계속 합산
3. `window.jtRfCalcCRE` 공개 함수가 `residentValue` 음수를 클램프하지 않음
4. 지수표기·전각숫자 파싱 실패
5. 기본값과 다른 선택지에 Tab+Enter 시 선택 무시(위저드 공용 버그)
6. 공동명의 1주택자가 특례 미신청이어도 자동으로 1세대1주택 세액공제 적용
7. 라우트 이동·새로고침 시 답변 전부 소실
8. 별거 배우자가 각자 주택을 보유해도 세대 판정 없이 "1채" 선택만으로 1주택 특례 적용

이 8건은 코드 상태가 그대로이므로 다시 물어도 똑같이 나온다. **완전히 새로운 카테고리만** 찾아라. 힌트:
- 인쇄·모바일 좁은 화면에서 레이아웃이 깨지는 곳.
- CGT↔CRE 반복 왕복 시 전역 상태 오염.
- "요약 카드"와 `RfSteps` 단계별 숫자의 반올림 불일치.
- 공시가격 합계가 음수이거나, 보유 주택 수가 "1채"인데 공시가격을 0으로 낸 경우처럼 모순 입력 조합.
- 세율표 구간 «경계값 정확히 그 금액»(예: 정확히 3억·6억·12억·25억·50억·94억)에서 부등호가 `>=` 인지 `>` 인지에 따라 세율이 한 구간 밀리는 off-by-one이 있는가.
- 다주택 공제 산식(`4억 + 5억 × 거주용가액/합계액`)에서 거주용가액이 합계액보다 «약간» 큰 경계(반올림 오차로 비율이 1.0000001이 되는 경우) 클램프가 실제로 작동하는가.
