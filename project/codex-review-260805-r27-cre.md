## 4. 검증 결과

- 붙여넣기/자동입력: 금액 입력은 `onChange`에서 숫자만 남기며, 주소 자동조회 금액도 `Number(r.amount)` → 합산 문자열로 전달된다. ASCII 숫자·쉼표 포함 붙여넣기와 정상 API 정수 금액에는 추가 파싱 결함이 없다. 기존 전각·지수 표기 이슈는 재보고하지 않았다. (`ReportReform2026.jsx:912-920`, `739`, `1263-1266`)
- 다중 탭: 계산 입력·결과·주소목록·에폭은 각각 React state/ref에 있고, 전역 `window`에는 불변 SSOT와 함수만 노출된다. 브라우저 탭은 별도 `window` realm이므로 탭 간 결과 공유 경로가 없다. (`:46-189`, `:1246-1266`)
- 소수 원 단위: 모든 화면 금액은 `rfWon()` 또는 `rfEok()`을 거치며 둘 다 `Math.round`를 적용한다. 소수 원이 그대로 노출되는 경로는 없다. (`:24`, `:29-41`, `:505-507`, `:539`)
- 연도 카드: 2026·2027·2028 계산은 동기식 `map`으로 전부 성공한 뒤 한 번에 `setResult`한다. 특정 연도에서 예외가 나면 `setResult` 이전에 전체 실행이 중단되므로, 해당 카드만 조용히 비거나 이전 값이 재사용되지는 않는다. (`:1278-1284`, `:487-518`)
- 세액공제 SSOT 및 상한: 연령 70세 이상 40%, 15년 이상 보유/거주 50%, 합계 상한 80%가 SSOT에 있고, 코드가 `Math.min(ac + hrRate, 0.80)`으로 적용한다. (`:170-183`, `:436-452`)
  - 재현: 70세·보유/거주 20년·2026년이면 `40% + 50% = 90%`이나 정확히 `80%`로 절단된다. 공시가 60억의 산출세액은 32,200,000원, 공제는 `32,200,000 × 80% = 25,760,000원`이다.
  - 2027년은 보유 25%와 거주 50% 중 50%를 선택해 `40% + 50% = 90% → 80%`; 2028년 역시 거주 50%를 써 동일하다. 공시가 24억이면 산출세액 4,900,000원, 공제 3,920,000원으로 80%가 수치상 확인된다. 금액 한도(2027년 800만원, 2028년 600만원)는 공제를 더 줄일 뿐 90%·100%가 새는 경로는 아니다.
