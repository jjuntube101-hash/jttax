## 1. 작업 요약

신규 발견 1건: 소수부가 포함된 금액을 붙여넣으면 소수점을 제거하지 않고 숫자를 이어 붙여 세액이 최대 100배 왜곡됩니다.

## 2. 변경 내역

변경 없음 — read-only 검토.

- [등급 P2] · [ReportCrypto2027.jsx](/D:/jt-data/jttax-cta/project/src/ReportCrypto2027.jsx:133) · `CrMoney`가 붙여넣은 값에서 숫자가 아닌 문자를 모두 제거해 `50,000,000.00`을 `5000000000`으로 저장합니다.

  재현 입력값: 이전부터 보유한 코인 1행에 판 금액 `50,000,000.00`, 실제 산 금액 `10,000,000.00`, 2026.12.31 시가 `40,000,000.00`을 붙여넣기.

  잘못된 출력: 양도가액 50억 원, 필요경비 40억 원, 소득금액 10억 원, 총세액 **219,450,000원**.

  올바른 값: 양도가액 5,000만 원, 필요경비 4,000만 원, 소득금액 1,000만 원, 총세액 **1,650,000원**.

  수정안: 원 단위 입력은 그룹 구분자만 제거하고, `.00`은 정수로 정규화하거나 `.01` 등 소수부가 있으면 검증 오류를 표시해야 합니다. 현재처럼 소수점을 삭제해 숫자를 연결하면 안 됩니다.

## 3. 재발 방지

`50,000,000.00` 붙여넣기 시 저장값이 `50000000`이고 총세액이 `1,650,000원`인지 확인하는 UI/파서 회귀 테스트가 필요합니다.

## 4. 검증 결과

`Get-Content -Encoding utf8`으로 원본을 확인했습니다.

- 133~135행: 숫자 외 문자를 제거하는 입력 파서 확인.
- 75~99행: 저장된 값으로 필요경비·세액을 계산하는 경로 확인.
- 동일 로직으로 계산한 결과: `{"sale":5000000000,"expense":4000000000,"income":1000000000,"taxBase":997500000,"tax":199500000,"local":19950000,"total":219450000}`.

나머지 요청 항목은 신규 결함 없음입니다.

- 탭 간 전역변수: `window`는 탭별로 분리되며, `JT_CRYPTO_2027`·`jtCrCalc`는 이 파일에서만 정의됩니다. 입력값은 컴포넌트 로컬 state입니다.
- 소수점 이하 원 단위 노출: 모든 원화 표시가 `Math.round`를 거쳐 표시됩니다.
- 행 전체 삭제: 마지막 행은 삭제할 수 없고, 빈 행이면 계산 버튼이 비활성화됩니다. 0개 행으로 0원 계산되는 경로는 없습니다.
- 보유 구분 토글: 2026년 말 시가는 state에 남지만 `2027년 이후 취득`일 때 계산식이 이를 사용하지 않습니다. 다시 이전 보유로 바꿀 때만 재사용됩니다.
