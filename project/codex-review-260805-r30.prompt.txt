## R29에서 당신이 지적한 3건을 이렇게 반영했다 (이 반영이 옳은지 검증하라)

1. **[P1] §37⑥ 행별 적용** → 자동 합산 대신 **「한 종목당 한 줄」을 입력 단계에서 강제**했다.
   `crValidateRows()` 를 순수 함수로 분리(`window.jtCrValidateRows`)하고, 2줄 이상이면
   ①코인 이름 필수 ②이름 중복(공백·대소문자 무시) 시 거부한다. 안내문도 「한 종목당 한 줄,
   같은 코인은 그 해 합계를 한 줄에, 산 금액은 총평균 단가로」로 고쳤다.
   **판단 근거**: 자동으로 합치면 사용자가 무엇이 합쳐졌는지 모르고, 이름이 비면 합칠 근거도
   없다. 또 이 계산기는 §37⑤·§88①·§37⑥ 세 규정이 «전부» 종목 단위라 행=종목이 설계 전제다.
   → 이 접근이 §37⑥ 문언(「같은 종류의 가상자산 전체의 총양도가액」)을 충족하는가?
     자동 합산이 아니라 입력 강제로 푸는 것이 타당한가? 우회 경로가 남아 있는가?

2. **[P1] stillLiving='no' + seniorLive2y='yes' 모순** → **세 겹으로** 닫았다.
   ①`seniorLive2y` 문항의 showIf 에 `a.stillLiving === 'yes'` 추가
   ②`onChange` 에서 stillLiving 이 'yes' 가 아니게 되거나 resYears 가 0 이하가 되면
     `seniorLive2y` 를 'no' 로 함께 내림(숨기기만 하면 옛 값이 남는다)
   ③`rfCalcCGT` 안에서도 `input.stillLiving !== 'no'` 를 요구(공개 함수 방어)
   **재현 확인**: 당신이 준 시나리오에서 이사함 → 70,653,000원, 계속거주 → 35,326,500원.
   → 세 겹이 서로 모순되지 않는가? `stillLiving` 미지정(외부 호출·기존 테스트)에서
     하위호환이 깨지지 않는가? 다른 모순 조합이 남아 있는가?

3. **[P3] 코인명 aria-label** → 추가함.
