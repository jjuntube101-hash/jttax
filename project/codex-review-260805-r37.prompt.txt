## R36 지적을 전면 채택했다
「CASE 20b 가 엔진 세액만 고정하고 정작 고친 결론 로직은 검사하지 않는다 —
결론이 `diff === 0` 으로 퇴행해도 전부 통과한다」는 지적이 정확했다.
(내 메모리에도 「게이트를 «만드는 것»과 «작동하는 것»은 다른 일」이 교훈으로 남아 있는데
 이번에 똑같이 반복했다.)

### 반영
1. 결론 판정을 **순수 함수 `rfCreVerdict(rows)` 로 분리**해 JSX 앞(테스트 하네스 실행 범위)으로
   옮기고 `window.jtRfCreVerdict` 로 공개했다. 반환: `{kind:'none'|'same'|'changed', diff,
   base, last, mid, midDiffers, anyNotTaxable}`.
2. JSX 는 이제 «문장만 고른다» — `v.kind`·`v.midDiffers`·`v.diff` 만 읽는다.
3. 회귀 8항 추가: R35 반례에서 `kind==='changed'`·`midDiffers===true`·`diff===0` 을 동시에
   단언(=`diff` 만 보면 틀린다는 것을 테스트가 «직접» 잡는다) + `none`/`same`/2028만 다름/
   문턱 미달 섞임 갈래를 각각 고정.

### 실측 (Claude 실행 — 당신 환경엔 node 가 없다)
- `npm run gate` 전 항목 통과. CASE 20b 12항 전부 PASS.
- 브라우저 실동작(R35 반례 입력): 결론문이
  「2028년 이후 종부세는 현행과 같은 230.4만원입니다. 중간의 2027년은 207.3만원으로, 현행보다 23만원 적습니다.」
  — 종전이라면 「달라지지 않습니다」였다.

## 무엇을 볼 것 (이 편집만)
- `rfCreVerdict` 분리가 화면 동작을 바꾸지 않았는가(문장 선택이 종전 의도와 동일한가).
- 회귀 8항이 «퇴행을 실제로 잡는» 테스트인가. `diff === 0` 으로 되돌리면 어떤 항이 실패하는가.
- `kind`/`midDiffers`/`anyNotTaxable` 판정이 빠뜨리는 조합이 있는가.
- R23~R36 반영분 회귀.
