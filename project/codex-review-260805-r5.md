## 2. 지적 사항

- [P1] · `project/src/ReportReform2026.jsx:561, 570, 579-605, 749-750` · 조회 순번 `seq`가 `RfAddrLookup` 인스턴스별 ref입니다. 조회 A를 시작한 뒤 다른 문항으로 이동하면 해당 컴포넌트가 언마운트되고, 복귀 후 조회 B는 새 `seq`를 사용합니다. 따라서 늦은 A 응답도 자기 옛 `seq`에서는 최신으로 판정됩니다. B의 자동입력은 `gens`를 올리지 않으므로 A가 B 값을 다시 덮습니다. `showIf`로 주소 문항이 사라졌다 나타나는 경우도 동일합니다.

  재현 입력값과 잘못된 출력: 종부세 화면에서 `1주택·거주·50세·보유 1년·거주 0년`을 입력합니다. 공시가격 합계에 임시로 10억 원을 입력한 뒤 주소 A 조회(응답 `30억 원`)를 시작하고 다음 문항으로 이동했다가 돌아옵니다. 주소 B 조회(응답 `10억 원`)를 실행해 먼저 완료시킵니다. 이후 A 응답이 도착하면 화면 값은 다시 **30억 원**이 됩니다. 2026년 표시세액은 `(30억−12억)×60%=10억8천만 원`, 종부세 `840만 원` + 농특세 `168만 원` = **10,080,000원**입니다. B의 10억 원이면 공제 12억 원 이하이므로 정답은 **0원**입니다.

  수정안: `seq`를 위저드의 문항 ID별 ref로 올리거나, `RfAddrLookup`의 unmount cleanup에서 `seq.current`를 증가시켜 진행 중 요청을 무효화하십시오. 응답 반영 조건은 “문항별 조회 순번 일치”와 “입력 세대 일치”를 함께 확인해야 합니다.

- [P1] · `project/src/ReportReform2026.jsx:651-658, 604-605, 951-953` · 다주택자의 **공시가격 합계** 문항에도 단일 주소 조회 결과를 그대로 `totalValue`에 넣습니다. 주소 하나의 공시가격을 여러 주택의 합계로 오인해 종부세가 과소 계산됩니다.

  재현 입력값과 잘못된 출력: `2주택·조정대상지역 아님·거주용 주택가액 0원`에서 공시가격이 각각 10억 원인 두 주택을 보유했다고 가정합니다. 합계 문항의 주소 조회로 한 주택(10억 원)만 조회하면 자동입력값은 **10억 원**입니다. 2026년 화면 출력은 과세표준 `(10억−9억)×60%=6천만 원`, 종부세 30만 원 + 농특세 6만 원 = **360,000원**입니다. 실제 합계 20억 원이면 과세표준은 `(20억−9억)×60%=6억6천만 원`, 종부세 `150만+210만+60만=420만 원`, 농특세 84만 원으로 **5,040,000원**이어야 합니다. 즉 **4,680,000원 과소**입니다.

  수정안: `houses !== 'one'`이면 합계 문항의 주소 자동입력을 숨기고 “모든 주택 공시가격의 합계 직접 입력”만 허용하거나, 주택별 행 입력·합산 기능을 구현하십시오.
