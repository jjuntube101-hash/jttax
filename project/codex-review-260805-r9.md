## 2. 지적 사항

- [P1] · [ReportReform2026.jsx:586](/D:/jt-data/jttax-cta/project/src/ReportReform2026.jsx:586), [598](/D:/jt-data/jttax-cta/project/src/ReportReform2026.jsx:598), [698](/D:/jt-data/jttax-cta/project/src/ReportReform2026.jsx:698), [756](/D:/jt-data/jttax-cta/project/src/ReportReform2026.jsx:756), [890](/D:/jt-data/jttax-cta/project/src/ReportReform2026.jsx:890) · 주소로 `조정대상지역`을 조회한 뒤 문항을 넘기거나 결과를 제출해도 에폭을 올리지 않습니다. 늦은 응답은 정상으로 판정되어 `adjusted`만 뒤늦게 바꾸지만, `result`는 변경 전 답으로 이미 고정되어 표시 세액과 실제 입력 상태가 갈라집니다.

  재현: 양도가 15억, 취득가 8억, 필요경비 0, 3주택, 보유 6년, 거주 0년, 50세를 입력합니다. `조정대상지역` 문항에서 실제 조정대상지역 주소 A를 조회하고 응답 전에 다음 문항들로 넘어가 결과를 제출합니다. 당시 기본값 `adjusted=no`로 표시되는 2026 총세액은 **243,903,000원**입니다. 이후 A 응답이 `yes`를 넣어도 결과는 그대로입니다. 실제 조정대상지역 3주택이면 장특공제 배제, 과세표준 697,500,000원, 산출세액 `697,500,000×72%−35,940,000=466,260,000원`, 지방소득세 46,626,000원으로 **512,886,000원**이어야 합니다.

  수정안: 문항 이탈과 결과 제출 직전에 해당 문항의 부모 에폭을 증가시켜 진행 중 조회를 취소하십시오. 또는 조회 중에는 다음/제출을 막으십시오. `onRegion`도 현재 응답 에폭이 유효할 때만 반영되어야 합니다.

FAQ의 “2028년부터 주택 수와 관계없이”라는 서술과도 충돌합니다.

  재현: 3주택, 거주용 주택가액 0원, 공시가격 합계 1,828,571,430원은 2027년 과세표준 1,000,000,001원입니다. 코드상 종부세 산출세액은 `3억×0.5% + 3억×0.7% + 약4억×1.0% = 7,600,000원`, 농특세 포함 **9,120,000원**입니다. 랜딩 표의 1.3%를 따르면 산출세액 8,800,000원, 총 **10,560,000원**으로 잘못 이해하게 됩니다.

  수정안: 표를 `1·2주택 1.3% / 3주택 이상·조정지역 1.0%`로 분리하거나, 1.3% 행에 적용 대상을 명시하십시오.

## 3. 재발 방지

주소 조회 E2E에 “조회 시작 → 문항 이탈 → 제출 → 늦은 응답”을 추가하고, 결과 제출 후 `answers`가 바뀌지 않음을 검증해야 합니다.

- `git show HEAD`로 R8의 부모 `epochsRef` 이관과 주소 `onChange` 취소 처리를 확인했습니다.
- `git diff --check HEAD^ HEAD` 통과.
